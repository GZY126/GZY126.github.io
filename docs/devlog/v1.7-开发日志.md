## 一、项目概述

SimpleDrawBot 是一个 Android 平板应用，通过悬浮窗 + 无障碍服务实现在任意应用（便签、画板、相册）上自动绘制简笔画。

核心流程：
```
用户输入描述文字 → AI生成极简简笔画图片 → OpenCV提取轮廓 → AccessibilityService注入手势 → 绘制完成
```

同时支持搜图模式：在悬浮窗内置 WebView 中通过百度搜图下载图片，提取轮廓后绘制。

### 4.4 DrawingAccessibilityService — 无障碍手势注入

**功能**：通过 Android AccessibilityService 的 `dispatchGesture()` API 注入触摸手势。

**核心绘制流程**：
```kotlin
fun startDrawing(template: DrawTemplate, rect: RectF, durationSeconds: Int, callback: (Boolean) -> Unit) {
    drawingJob = CoroutineScope(Dispatchers.Default).launch {
        // 1. 计算总笔画长度，按比例分配时间
        val totalLength = strokes.sumOf { approximateStrokeLength(it.points) }
        
        // 2. 按长度比例分配每笔 duration
        val durations = strokes.map { 
            (it.length / totalLength * totalAvailableMs).toLong()
        }
        
        // 3. 逐笔绘制
        for ((index, stroke) in strokes.withIndex()) {
            if (!isDrawing) break
            executeStroke(stroke, rect, durations[index], interStrokeDelays[index], index)
            delay(interStrokeDelays[index])
        }
    }
}
```

**手势注入实现**：
```kotlin
private suspend fun executeStroke(...) {
    // 反归一化：0~1 坐标 → 屏幕绝对坐标
    val screenPoints = points.map { point ->
        PointF(
            rect.left + point.x * rect.width(),
            rect.top  + point.y * rect.height()
        )
    }
    
    // 速度倍率应用
    val speedFactor = 1.0f / speedMultiplier.coerceIn(0.25f, 4.0f)
    val duration = (baseDuration * speedFactor).toLong()
    
    // 使用 GestureDescription 构建手势
    val builder = GestureDescription.Builder()
    
    // 起笔 (ACTION_DOWN)
    val click = GestureDescription.StrokeDescription(path, 0, duration)
    builder.addStroke(click)
    
    // 通过 suspendCancellableCoroutine 转为协程
    dispatchGesture(builder.build(), callback, null)
}
```

**速度控制**：
```kotlin
companion object {
    @Volatile
    var speedMultiplier: Float = 1.0f  // 外部可实时修改
}
// speedMultiplier 影响：
//   - 每笔 duration = baseDuration * (1/speedMultiplier)
//   - 笔画间 delay  = baseDelay * (1/speedMultiplier)
```

**关键设计**：

- 强调 "coloring book style" 和 "sticker style" 引导纯色轮廓

**生成流程**：
```kotlin

    // 1. 构建 prompt
    val prompt = buildSeedreamPrompt(description, complexity)
    
    // 2. 调用 API
    val imageUrl = callImageAPI(prompt, imageModel)
```

### 4.6 ImageContourExtractor — OpenCV 轮廓提取

**功能**：使用 OpenCV 将图片转换为归一化笔画坐标。

**算法流程**：
```
原图 → 缩放到512 → 灰度化 → 自适应二值化 → 形态学闭运算 → findContours → 过滤排序 → approxPolyDP → 归一化到0~1
```

**三种模式参数**：

| 参数 | SIMPLE | COMPLEX | MAX |
|------|--------|---------|-----|
| minArea | 20 | 10 | 5 |
| dpEpsilon | 3.0 | 1.5 | 0.8 |
| maxStrokes | 50 | 200 | 800 |
| adaptiveBlockSize | 15 | 13 | 9 |
| adaptiveC | 8.0 | 5.0 | 3.0 |
| closeKernelSize | 3 | 3 | 3 |

**核心代码**：
```kotlin
fun extract(bitmap: Bitmap, complexity: Complexity): List<Stroke> {
    val params = when (complexity) {
        Complexity.SIMPLE  -> PARAMS_SIMPLE
        Complexity.COMPLEX -> PARAMS_COMPLEX
        Complexity.MAX     -> PARAMS_MAX
    }
    
    // 1. Bitmap → Mat
    val src = Mat()
    Utils.bitmapToMat(bitmap, src)
    
    // 2. 缩放
    if (max(w, h) > 512) {
        Imgproc.resize(src, src, Size(newW, newH))
    }
    
    // 3. 灰度 → 自适应二值化
    Imgproc.cvtColor(src, gray, Imgproc.COLOR_BGR2GRAY)
    Imgproc.adaptiveThreshold(gray, binary, 255.0, 
        Imgproc.ADAPTIVE_THRESH_GAUSSIAN_C, Imgproc.THRESH_BINARY_INV,
        params.adaptiveBlockSize, params.adaptiveC)
    
    // 4. 闭运算（连接断开的线段）
    Imgproc.morphologyEx(binary, binary, Imgproc.MORPH_CLOSE, kernel)
    
    // 5. 轮廓提取
    Imgproc.findContours(binary, contours, hierarchy, 
        Imgproc.RETR_TREE, Imgproc.CHAIN_APPROX_SIMPLE)
    
    // 6. 过滤 → 排序 → 简化
    val valid = contours.filter { Imgproc.contourArea(it) >= params.minArea }
        .sortedByDescending { Imgproc.contourArea(it) }
        .take(params.maxStrokes)
    
    // 7. approxPolyDP 简化 + 归一化
    return valid.map { contour ->
        val simplified = MatOfPoint2f()
        Imgproc.approxPolyDP(approx, simplified, params.dpEpsilon, false)
        val pts = simplified.toArray().map { PointF(
            it.x / width,   // 归一化到 0~1
            it.y / height
        )}
        Stroke(pts, false)
    }
}
```

**OpenCV 集成**：使用 Maven 依赖 `com.quickbirdstudios:opencv:4.5.3.0`，无需手动安装 .so 文件。

## 五、关键技术决策

### 5.1 为什么用 Z-Image 而不是文生 SVG

早期尝试过让 AI 直接输出 SVG path 或结构化绘图指令，但 AI 生成的坐标和形状经常不可控。改用 **AI 生成图片 + OpenCV 提取轮廓** 的方案后：
- AI 只需要生成"像不像"的图片（模型擅长）
- 轮廓提取保证输出是连续的线条（确定性算法）

### 5.2 为什么用英文 Prompt

图像生成模型（Z-Image / Seedream）对英文 prompt 的理解明显优于中文：
- "coloring book style" 比 "填色书风格" 更准确
- 否定词 "NO shading, NO gradient" 比 "无阴影无渐变" 更可靠

### 5.3 为什么用 quickbirdstudios/opencv

- 预编译的 Maven 包，无需配置 CMake/NDK
- 不需要 Camera 权限（官方 opencv-android 依赖相机模块）
- 体积虽大但开发体验好

### 5.4 悬浮球 vs Activity

使用 `WindowManager.addView()` 直接添加到系统窗口，而非普通 Activity：
- 可以显示在任意应用上方
- 不打断当前应用的用户操作
- 需要 `SYSTEM_ALERT_WINDOW` 权限

## 十二、v1.4 Bug 修复详解

### 12.1 Bug #1: 绘制时屏幕乱闪（缓动多段 dispatchGesture）

**根因**：v1.3 的缓动实现使用 `GestureDescription.Builder.addStroke()` 添加多段 StrokeDescription，
每段完成时 `GestureResultCallback.onCompleted()` 都会触发一次，导致多次重复 dispatch、进度回调乱序，
绘制区域不断跳动。

**修复**：改为**单段 Path + 插值法**实现缓动。在 `buildEasedPath()` 中：
- 起笔段 (0~15%): 每两个原有点之间插入 2 个额外点（物理上更慢）
- 中段 (15%~85%): 正常通过
- 收笔段 (85%~100%): 同样插入额外点
- 用单段 `StrokeDescription` 完成整笔绘制，只触发一次回调

### 12.2 Bug #2: 选区无法拖到屏幕顶部

**根因**：底部按钮区占用屏幕 18%（82%~100%），两行按钮过于密集。平板屏幕大但按钮区占比过高，
且 `clampRectToScreen` 没有为顶部留安全边距。

**修复**：
- 按钮区从两行 18% 改为单行 10%（90%~100%）
- 7 个按钮（预设/比例/居中/贴边/保存/取消/确定）单行排列
- `clampRectToScreen` 顶部留 50px 边距，底部留 10% 按钮区边距
- 选区现在可以拖到屏幕任意位置（除底部按钮区外）

### 12.3 Bug #3: 绘制开始后悬浮窗不自动隐藏

**根因**：`autoHideDuringDrawing()` 只处理了 `collapsedView`（收起态），
如果悬浮球处于展开态（面板可见），面板不会隐藏。

**修复**：
- 增加展开态检测：若 `isExpanded=true`，先强制收起面板
- 隐藏时：收起面板 → 收起态移至左上角 → 透明度 30%
- 恢复时：恢复位置和透明度

### 12.4 Bug #4: 搜图 WebView 持续网络错误

**根因**：
1. JS 注入中 `MutationObserver` 回调使用了 `arguments.callee.caller`，在严格模式下报错
2. 整个 JS 没有 try-catch 包裹，一处报错可能阻断后续页面加载
3. 平板 UA 可能被百度移动端反爬策略拦截

**修复**：
- JS 代码全量包裹 try-catch，元素隐藏和点击取图独立 try-catch
- 移除 `MutationObserver`（无需动态监听页面变化，onPageFinished 时一次性注入即可）
- UA 改为三星平板 Chrome 125，绕过移动端反爬
- 选择器列表改用数组循环，代码更清晰

## 十三、v1.5 画面还原度优化详解

### 13.1 P0: Zhang-Suen 骨架细化（解决双线问题）

**问题**：AI 生成的是有粗细的黑色描边，OpenCV 提取轮廓时把粗线的「内外两条边界」都抓出来，画出来是平行双线、中间空心。

**实现**：二值化 → 闭运算 → **Zhang-Suen 骨架细化** → findContours

在 `ImageContourExtractor.kt` 中新增 `zhangSuenThinning()` 方法（纯手写约 60 行），将粗黑线条提炼成单像素中心线。两个子迭代交替剥离边界像素，直到只剩下骨架。

**效果**：粗线 → 单线，彻底消除双轮廓问题。

### 13.2 P1: 高斯模糊 + 碎线过滤 + 断点合并

| 改进 | 位置 | 效果 |
|------|------|------|
| 高斯模糊 3×3 | 灰度化后 | 抹平 AI 生成图的边缘锯齿，轮廓更平滑 |
| 周长过滤 `minLength` | 面积过滤后 | 丢弃周长 < 阈值的碎线，画面更干净 |
| 断点合并 `mergeNearbyEndpoints()` | 简化后 | 端点距离 < 0.015 的相邻笔画自动拼接，减少断笔 |

### 13.3 P1: 描粗三档 + 笔锋加重

`DrawingAccessibilityService` 新增 `ThicknessMode` 枚举：
- **细线**（offsetCount=0）：不做任何叠加
- **中粗**（offsetCount=1）：法线偏移 1 条平行线
- **粗线**（offsetCount=2）：法线偏移 2 条平行线

笔锋实现：首尾 15% 段落按渐变权重偏移叠加（t=0→0.15 渐强，t=0.85→1 减弱），中段保持单线不叠加。模拟「起笔重、行笔轻、收笔重」的手绘笔锋感。

### 13.4 P2: Prompt 优化

```

新: clean thin outline, single line art, NO stroke width variation, 
     NO double lines, NO overlapping strokes
```

从源头引导 AI 生成单线简笔画，配合骨架细化效果最佳。

### 13.5 UI 新增控件

- **线条粗细** RadioGroup：细线 / 中粗 / 粗线
- **单线模式** CheckBox：控制骨架细化开关（默认开启）

## 十六、v1.5 预览裁剪 + 笔画删除/撤回（2026-08）

### 16.1 预览区域裁剪

**功能**：在笔画预览图上拖动选择保留区域，去除文字、水印等不需要的笔画。

**实现逻辑**：
- `setupPreviewCrop(iv)` 设置 ImageView 的 OnTouchListener

- `renderPreviewBitmap()` 渲染时过滤中心点不在裁剪区域内的笔画，并在裁剪区域外绘制半透明遮罩

**功能**：单击预览图中的笔画即可删除（微调去除多余笔画），支持撤回防止误删。

**实现逻辑**：
- 在 `setupPreviewCrop` 中区分拖动和单击：移动距离 < 10px 视为单击
- 单击时调用 `deleteNearestStroke(normX, normY)`：遍历所有笔画找中心点距离最近的，保存到 `deletedStrokeHistory` 栈，从模板中移除

## 十八、v1.7 细节程度滑块 + 选区双指缩放（2026-08）

### 18.1 细节程度滑块

**问题**：轮廓提取是全量保留，小草、纹理等细碎装饰线全部保留，画面杂乱。

**方案**：按笔画包围盒面积排序，保留累计面积达 detailLevel% 的主体笔画。

**实现逻辑**：
- `detailLevel` 范围 10~100，默认 60
- `filterByDetailLevel()` 计算每个笔画的包围盒面积（maxX-minX）×（maxY-minY）
- 按面积降序排序，累计面积达到目标比例时截断
- detailLevel=20 → 极简只留主体外轮廓
- detailLevel=100 → 全量保留

**形态学开运算联动**：
- 核大小 = `(100 - detailLevel) / 20`，范围 1~5
- detailLevel 越小 → 核越大 → 更多小斑点被抹掉

**UI**：新增「细节程度」滑块（10~100，步长5），默认60

### 18.2 选区双指缩放 + 四边把手

| 操作 | 效果 |

| 双指捏合/张开 | 以选区中心为基准缩放 |
| 四角把手 | 同时调宽高 |
| 四边中间把手 | 上/下只调高度，左/右只调宽度 |
| 单指拖动 | 移动选区 |

### 18.3 改动文件

## 十九、v1.7 三路参数细化 + 伪闭合过滤 + 超精细模式（2026-08）

### 19.1 三路独立参数映射

一个 detailLevel 滑块内部拆成三个独立维度：

| 维度 | 控制内容 | 范围 | 默认 | 联动规则 |
|------|----------|------|------|----------|
| 开运算 | 去噪/去小斑点 | 0~4 | 1 | detail<20→4, <40→3, <60→2, <80→1, ≥80→关 |
| 闭运算 | 连线强度 | 0~3 | 0 | detail<20→3, <40→2, <60→1, **≥60→关闭** |
| 面积截断 | 细节保留比例 | 10%~100% | 70% | 线性映射 detailLevel/100 |

**关键**：闭运算在 60 以上关闭，从根源上避免相邻线条被粘成块。

### 19.2 伪闭合过滤

- 内轮廓(level≥1)且面积<20px 的直接丢弃
- 消除形态学产生的伪闭合碎块

### 19.3 超精细模式（detailLevel≥90）

| 参数 | detail<70 | detail≥70 | detail≥90 |
|------|-----------|-----------|-----------|
| dpEpsilon | ×1.0 | ×0.6 | **×0.3** |
| minArea | 线性 50→5 | 5 | **1** |
| 开运算 | 按档位 | 关闭 | 关闭 |
| 闭运算 | 按档位 | 关闭 | 关闭 |

### 19.4 兜底重试机制

第一次提取（aggressive=true）失败时自动降级重试（关闭开运算+低adaptiveC+dpEpsilon×0.6）。

### 19.5 预处理顺序修正

旧：二值化 → 闭运算 → 开运算 → 骨架
新：**二值化 → 开运算 → 闭运算 → 骨架**（先去噪再连线）

### 19.6 骨架细化保护

细化前微膨胀 1px，防止小圆圈缩成一个点消失。

### 19.7 小闭合轮廓强制保留

包围盒 < 0.008 的闭合圆（眼睛/纽扣）不参与截断，强制保留。
